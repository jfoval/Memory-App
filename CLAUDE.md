# CLAUDE.md — Memory Palace

Guidance for working in this repo.

## What this is

A free, multi-user Memory Palace trainer (Method of Loci). One **shared, fixed
52-location palace** is authored in code and identical for every user. Users only
add private **content sets** (≤52 items each) mapped onto the shared loci, plus a
card-deck mode. No generative LLM. Runs on free tiers.

## Commands

```bash
npm run dev         # Vite dev server
npm run typecheck   # tsc -b --noEmit (strict)
npm run lint        # eslint, zero warnings allowed
npm run test        # vitest (pure logic)
npm run build       # tsc -b + vite build (+ PWA)
npm run format      # prettier
```

Keep all four gates (typecheck, lint, test, build) green. Never commit a broken
build. Flag/split any file over ~300 lines.

## Conventions

- React 18 + TS strict. Function components. Tailwind for styling (utility
  classes + a few `@layer components` helpers in `src/index.css`).
- State: **Zustand** for UI/nav/game state (`src/store`, `src/auth`),
  **TanStack Query** for server data (`src/data/hooks.ts`).
- Domain types are camelCase (`src/types.ts`); the Supabase backend maps them
  to/from snake_case columns.
- Pure logic lives in `src/logic/*` and must stay framework-free and unit-tested.

## The shared palace

- `src/palace/zones.ts` — 4 zones (Garden Court, Kitchen Wing, Library Hall,
  Observatory Tower), each mapped to a card suit, with a floor origin.
- `src/palace/palaceData.ts` — 52 authored loci (name, landmark, shape, color),
  positions generated by a deterministic serpentine per zone (clear spacing).
  `PALACE` is the exported `Locus[]`; integrity is enforced by tests.
- Rendering: `src/scene/LocusObject.tsx` picks geometry by `shape` behind one
  component so primitives can be swapped for richer models later.

## Navigation

- `src/scene/Player.tsx` — first-person controller. Desktop: WASD/arrows +
  pointer-lock mouse-look (drag fallback). Touch: joystick + drag-look fed via
  `src/store/navStore.ts`. Guided walk glides to a locus and faces it.
- `src/scene/collision.ts` — pure: clamp to world bounds + push out of per-locus
  keep-out circles (player can't clip or get stuck). Unit-tested.
- Perf budget in `src/scene/PalaceCanvas.tsx`: dpr clamped to 2, render loop
  paused when hidden, cheap lighting/shadows.

## Data model & isolation

Tables (Supabase): `profiles`, `content_sets`, `items`, `reviews`,
`card_results`. **RLS on every table** (`user_id = auth.uid()`), defined in
`supabase/schema.sql` alongside owner-scoped Storage policies.

`src/data/backend.ts` defines `DataBackend`. Two implementations:
- `localBackend.ts` — localStorage; used when no Supabase keys (and as offline
  cache shape). Lets the whole app run without a backend.
- `supabaseBackend.ts` — Postgres + RLS.

`repository.ts` selects the backend, keeps a local mirror, and queues offline
review/card writes for replay on reconnect (last-write-wins via `updatedAt`).

## Scoring & scheduling

- `src/logic/scoring.ts` — `normalize`, `jaccard`, `levenshtein`, `cosine`,
  `lexicalScore`, `scoreAnswer` (lexical always; semantic blend when embeddings
  present), `band`, `buildChoices`. Weights are named constants.
- `src/embeddings/` — Transformers.js MiniLM in a Web Worker; `embeddingService`
  exposes `embed()` that returns null when unavailable (lexical fallback).
- `src/logic/scheduling.ts` — SM-2 (`review`, `scoreToQuality`, `isDue`).

## Auth

`src/auth/authStore.ts` (Zustand). Supabase email auth when configured; otherwise
local demo accounts (deterministic uid per email) so features work without keys.

## Adding a screen

Add to `src/app/screens`, register a tab in `src/store/uiStore.ts` + the
`TABS` array in `src/app/AppShell.tsx`.

## Notes

- Keys `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` are public by design.
- The only server-side code is the URL-import function (`api/import.ts` +
  `netlify/functions/import.ts`), sharing `src/logic/readability.ts`.
